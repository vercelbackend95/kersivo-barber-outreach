# Kersivo Pilot Proof Framework (Pre-Case-Study)

This file defines how to collect credible proof before public case studies exist.
Do not present assumptions as outcomes.

## Positioning rules (non-negotiable)
- Never claim "proven uplift" or "verified improvement" without complete evidence.
- Clearly label pilot metrics as `in progress` until windows are complete.
- Only publish numbers that have source screenshots and owner approval.
- Use shop-owned source systems only (booking exports, Stripe, logs, admin records).

## Shared KPI definitions
- `utilizationRate`: booked slots divided by available slots.
- `noShowImpactGBP`: estimated value of no-shows plus late cancellations.
- `ownerOpsHoursWeekly`: owner/admin hours spent on scheduling coordination.
- `retailAttachRate`: retail orders linked to booking traffic.
- `timeToConfirmBooking`: average minutes from customer intent to confirmed booking.

## Pilot evidence pack template
- Pilot ID: `ksv-pilot-xx`.
- Shop profile: chair count, location type, staffing model.
- Offer model used: `Launch SaaS` or `Priority Growth`.
- Baseline window: minimum 28 days before go-live.
- Post-launch window: same length as baseline.
- Data sources: list exact exports/reports used.
- Owner quote status: `pending` or approved quote with identity.

## First three pilot profiles to prioritize
1. `ksv-pilot-01`: city shop, 3-4 chairs, owner-led scheduling pressure.
2. `ksv-pilot-02`: growth shop, 5-6 chairs, adding barbers and shift complexity.
3. `ksv-pilot-03`: premium shop, 4-8 chairs, active retail and margin sensitivity.

## Pre-proof messaging snippets (safe to use now)
- Snippet A: "We focus on UK barbershops with 3-8 chairs and run rollout as a guided implementation, not a DIY setup."
- Snippet B: "For each pilot we track utilization, no-show impact, and owner ops hours with equal before/after windows."
- Snippet C: "We can share KPI definitions and measurement method first, then publish full case studies once evidence windows complete."

## Landing proof block (before case studies exist)
1. Segment tag (for example: "4-chair city shop").
2. One-line pain statement.
3. "What we measure" bullets (not outcomes yet).
4. Pilot status line (`baseline complete`, `post-launch collecting`, etc.).
5. Method note that explains window length and data sources.
